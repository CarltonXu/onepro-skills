# Q&A generation guidelines (EN + ZH)

This skill assumes the Q&A *content* is generated by the model, while scripts enforce *format*, *hashing*, and *safe sync*.

## Goals

- Produce high-signal, searchable Q&A that matches OnePro user intent.
- Keep Q&A stable across re-runs (same `source_id`).
- Keep English and Chinese aligned where possible (same category taxonomy; localized wording).

## Recommended categorization

Use a small, stable taxonomy like:

- HyperBDR / Install
- HyperBDR / Backup
- HyperBDR / Restore
- HyperMotion / Install
- HyperMotion / Agent
- Portal / Account & Billing
- Portal / Troubleshooting
- Security / Access
- Networking / Ports & Firewall
- FAQ / Concepts

Keep categories consistent (avoid near-duplicates like “Install” vs “Installation”).

## Writing rules

- Titles should be a real user question.
- `question_md` should include context and constraints (OS/product/version) when relevant.
- `answer_md` should be actionable:
  - What it means
  - Why it happens
  - How to fix / verify
  - What to collect for escalation
- Add `tags` for product, module, OS, and error keywords.
- Add at least 1 `source_urls` per item for traceability.

## Stable `source_id`

Pick a stable scheme and **do not change it** once published.

Suggested format:

`docs:<path>#<section-id>`

Example:

`docs:/hyperbdr/backup/retention#how-retention-works`

If there is no stable section id, use a short slug you control.
